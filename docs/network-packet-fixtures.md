# Disposable network packet fixtures

`tests/fixtures/network/network_packet_fixture.py` is an original, standard-library Python fixture for parent-operated observations on a **new, unused Virmill NAT or lab network** in the approved disposable VM. It creates two temporary network namespaces and two veth pairs, then removes only those objects after checking their identities. It never creates, changes, restarts or removes the selected libvirt network. It does not start a guest, change host firewall rules or sysctls, install software, or configure a production host.

The implementation contributes packet-observer prerequisites for **NET-01, NET-02, NET-03 and NET-05** in the normative acceptance package. Namespace endpoints do not qualify real guest routing, persistent guest configuration, a guest with three NICs, physical networking, or a services-only firewall adapter. The current fixture accepts only explicit `hostAccess=allow`. Services-only execution is deliberately unavailable until the product has an applicable firewall implementation. Every report sets `fullNetworkAcceptance=false` and `guestOrHardwareQualification=false`.

## Parent execution boundary

Only the parent/operator may execute this fixture on the already authorized disposable VM. Required `--root` selects an existing, canonical, nonsymlink direct child of:

```text
/home/virmill-test/virmill-tests
```

The selected child is the parent's new isolated run directory, not an inferred historical run. Root-only, relative, nested, noncanonical, control-bearing and symlink paths are refused. No old run journal is touched. Before execution, the parent must create and identify the new network through Virmill's reviewed workflow, inspect its creation/job binding, and exclude concurrent network/guest/namespace mutations throughout the fixture window. A Virmill XML marker is checked as a structural prerequisite; it is not treated as an authority grant or proof of ownership. The explicit `--confirm-new-unused-network` records the parent's external ownership check. This fixture is not safe for adoption of an existing/shared network.

Required remote facilities are Linux network namespaces, nsfs bind mounts under `/run/netns`, veth and bridge support, root on the selected disposable host with `CAP_SYS_ADMIN`/`CAP_NET_ADMIN`/`CAP_NET_RAW`, access to read-only `qemu:///system` libvirt inventory, and these already installed binaries:

```text
/usr/bin/python3
/usr/bin/virsh
/usr/bin/ping
/usr/bin/ip (or /usr/sbin/ip)
```

No DHCP client package or tcpdump installation is required. Distribution binary symlinks are resolved to root-owned, non-group/world-writable regular files and recorded with hashes. Selected source and output paths refuse symlink components. Workers run the same hash-pinned source using isolated Python (`-I -B`) and a fixed minimal subprocess environment. Worker entry refuses the calling host network-namespace inode and requires its generated peer interface alias before opening sockets.

The fixture requires an active, persistent, autostart-off network, exactly matching UUID-derived `virmill-UUID` and `vm` plus the first twelve lowercase UUID hex digits. It checks a version-1 creation marker, exact live XML SHA256, NAT versus no-forward lab shape, one private IPv4 subnet with room for two endpoints, expected DHCP mode, no static DHCP reservations, the bridge gateway/address/prefix, and an empty bridge port list. An existing port, identity mismatch or unavailable prerequisite causes refusal. It checks the bridge/XML again immediately before attaching each owned veth, and after cleanup. No physical interface is accepted.

Use a newly generated, canonical, nonzero run UUID for each attempt. Output must be exactly `ROOT/network-packet-RUN_UUID`; exclusive creation and retention make that run UUID single-use. A failed run is not retried with the same UUID or silently reused output. The source SHA is the reviewed program bytes. The XML SHA is the SHA256 of **exact stdout**, including the trailing newline, from this read-only command on the selected approved VM:

```text
/usr/bin/virsh --readonly -c qemu:///system net-dumpxml NETWORK_UUID
```

Parent invocation template; every uppercase placeholder must be resolved from the parent's reviewed inputs, not guessed:

```text
/usr/bin/python3 -I -B /ABSOLUTE/FROZEN/network_packet_fixture.py run
  --execute-reviewed --confirm-new-unused-network
  --root /home/virmill-test/virmill-tests/NEW_ISOLATED_RUN
  --recipe-sha256 REVIEWED_SOURCE_SHA256
  --run-id NEW_RUN_UUID
  --network-id NEW_NETWORK_UUID
  --network-xml-sha256 EXACT_LIVE_XML_STDOUT_SHA256
  --bridge vmLOWERCASE12HEX
  --kind nat --host-access allow --dhcp on
  --output /home/virmill-test/virmill-tests/NEW_ISOLATED_RUN/network-packet-NEW_RUN_UUID
```

The template shows argv on separate lines for review, not a shell script. Parent code should invoke a list of literal argv elements. Use `--kind lab --dhcp on` for managed lab DHCP. For the static lab profile use `--kind lab --dhcp off --static-a4 ADDRESS_A --static-b4 ADDRESS_B`; both addresses must be distinct ordinary unicast addresses in the exact native subnet and must exclude its network, broadcast and gateway. No prefix is included in these address arguments; the pinned native subnet supplies it.

For a DHCP-enabled network, static overrides are refused because the Virmill pool may cover every usable guest address. The fixture creates two locally administered MACs derived from the run UUID, acquires its own OFFER/ACK pairs, checks the offer before REQUEST, checks the ACK against that offer, and validates server ID, native pool, subnet mask and at least a 300-second lease before assigning each address to its own namespace. It rejects duplicate assigned addresses. It leaves only its own server-side lease records on the disposable network; it does not read or modify a DHCP lease file or send RELEASE for anyone else.

Optional probes require deliberate inputs:

```text
--dns-name APPROVED_NAME
--forward4-target APPROVED_IPV4_LITERAL --forward4-port APPROVED_TCP_PORT
```

`--dns-name` makes one bounded A query through the selected bridge's gateway only. The report separately says whether that server appeared in the fixture ACK. A recursive DNS query may cause upstream traffic; supplying the name is an explicit choice to run that query. Without this flag DNS remains `not_tested` even if DHCP advertised a DNS server.

The forwarding probe makes one bounded TCP connection to the explicit target and port, sending no application payload. The target must be outside the selected subnet. Only that target's `/32` route is added via the pinned gateway, inside namespace A. No default route is installed. The report labels this a fixture-supplied route, so it cannot be mistaken for a DHCP-installed guest default. NAT expects a connection; lab expects no connection. A failed connection has its errno/reason retained and does **not** prove filtering: an independently verified reachable target/control path is required for a later enforcement claim. No target means `not_requested`; no public address or Internet test is silently selected.

## Observations and interpretation

The two endpoints use their own lease addresses or approved static addresses. IPv4 ping tests peer reachability. A temporary TCP listener binds only the exact bridge IPv4 address and device on a kernel-selected port, confirms `SO_ACCEPTCONN`, and sends a run-specific token to namespace A. Success requires receipt of that token; the listener is stopped and closed before cleanup. Because this profile requires host access allow, failed access is a fixture failure, never fabricated services-only success.

DHCP evidence contains exact generated DISCOVER/REQUEST frames and the matched OFFER/ACK frames, checksums/hashes and decoded router/DNS fields. Lab passes the router-option check only when option 3 is absent and neither route option 121 nor 249 is present; unimplemented alternative route encodings do not establish suppression. NAT requires option 3 to contain exactly the pinned gateway and also refuses to interpret alternative route options. No advertised router, DNS or route is automatically applied. DHCP-off execution verifies static reachability but does not claim packet-level absence of a DHCP server.

Captured DHCP replies validate bounded Ethernet/IPv4/UDP/BOOTP framing and identity before their fields can be used. Duplicate options, overloaded options, fragments, malformed lengths, missing cookie/end/type/server, invalid router/DNS sizes and ordinary bad checksums are refused. Linux `PACKET_AUXDATA` checksum status is retained: veth may expose a checksum awaiting offload completion. Such a frame is labeled `kernel_partial`, not falsely described as a verified wire checksum; `kernel_valid` and full `wire` validation remain distinct. This is a narrow DHCP observer, not a complete RFC client, a packet-authentication scheme, or a parser for arbitrary PCAP formats.

IPv6 link-local addresses are observed after a bounded DAD wait. Where both endpoints have ready link-local addresses, a scoped IPv6 peer ping is attempted. The fixture sends a router solicitation from its own link-local address and observes up to five seconds of RA traffic only on that fresh peer interface. It validates direct ICMPv6 RA framing, checksum, hop limit 255, link-local source and bounded options, then reports router lifetime and prefix information. Extension-header RAs are explicitly outside the parser. No RA seen in that window is not proof of absence. No IPv6 sysctl is changed, and global/bridge forwarding and disable settings are read only for context.

The current native profile declares IPv6 disabled. Observed IPv6 link-local delivery or any accepted RA sets `ipv6DisabledContradictedByObservedTraffic=true`. An `ipv6="no"` XML declaration is not promoted to packet isolation. IPv6 external forwarding remains explicitly untested for this IPv4-only profile; a future reviewed IPv6 profile, explicit addresses/gateway/targets and packet controls are required. `ipv6IsolationProven` stays false. This distinction can make IPv4 checks pass while the overall fixture reports a policy discrepancy.

Reports retain individual observations even if an expectation fails. Final `scoped_checks_passed` requires the requested IPv4 checks, no observed contradiction to IPv6 disabled, and verified cleanup. This status still does not certify guest routing or unobserved IPv6 paths. `failed_or_policy_discrepancy` preserves errors and successful component observations. `manual_review_required` cleanup prevents a passed result and requires inspection of the original run; it never authorizes blind cleanup or retry.

## Retention, limits and cleanup

The output includes `invocation.json`, `prerequisites.json`, `preflight.json`, an fsynced `mutation-intent.json`, `commands.jsonl`, per-endpoint DHCP evidence when applicable, `observations.json` and final `report.json`. The command journal records literal argv and intent before execution, deadline, return code, bounded stdout/stderr and interruption. Native replies are not shell-evaluated. Captured traffic is confined to the new peer interface; only correlated DHCP/RA/DNS bytes and own generated packets are retained, not broad host captures.

Each native command has a deadline; the command/output journal has a 240-command and 8 MiB aggregate bound, 256 KiB per stream, and the normal command phase has a 180-second deadline. DHCP has two nine-second phases per endpoint with at most 512 inspected packets each; RA has five seconds and at most 512 packets; Ethernet frames are at most 2048 bytes; DNS responses at most 4096 bytes; TCP and DNS operations have three-second socket deadlines. Cleanup gets a separate 60-second command opportunity. Any exhausted bound is a failure, not a success substitute.

Namespace names contain the full run UUID. Veth names use a short UUID component within Linux's interface-name length, and each host/peer has a full run-UUID alias. Cleanup compares each acknowledged host veth's recorded ifindex, exact name, alias and veth kind. It compares each namespace's held nsfs device/inode against its nonsymlink name and requires no remaining processes before removing the name. It never kills an unrelated namespace process. A lost creation acknowledgement, replacement, unfamiliar object, PID, inability to inspect or cleanup failure is retained for manual review. Name checks and native operations are not an atomic compare-and-delete API; the parent must keep the explicitly exclusive window. SIGINT/SIGTERM attempt bounded cleanup. SIGKILL/power loss cannot guarantee cleanup; the durable intent and command journal identify objects for human review, not automatic replay.

The bridge, its addresses, native XML, global routes, firewall and network definition are never cleanup targets. The tool does not flush firewall rules, disable host IPv6, delete the selected network, destroy VMs, touch source media or inspect TPM/NVRAM/key/state bytes. The ordinary `ip netns` implementation may establish its standard `/run/netns` infrastructure; the fixture does not remove that shared infrastructure. Root privileges and native capabilities remain unqualified until the parent records an actual disposable-host run.
