# Cold auxiliary capture endpoint readiness

The file-pinning and sealed-descriptor primitives are ready to be composed into a narrowly authorized executor. **The privileged capture endpoint, native auxiliary-member binding and durable publication proof do not exist yet.** Adding an operation name to the helper allowlist would not supply those missing checks.

This is an implementation-readiness review of ADR 0020 and the current helper/cold-source code. It selects no new architecture or public contract and certifies no security or native recovery scenario. The inspected helper/coldfiles/domain/ADR files had no working-tree changes at the final check; HEAD was `dc2ab1a7af8c023c1485d36d0e858a65264ace3e`. The root checkout changed during unrelated parent integration. Only this review file was written.

## Acceptance and authority boundary

The supplied [acceptance table](../../virmill-v1-spec/docs/13-testing-and-acceptance.md) maps SNAP-01 to cold snapshot/revert preserving disks, configuration and required firmware/TPM identity; SEC-01 to rejecting wrong peers/unauthorized helper actions; and JOB-02 to observation-based recovery of uncertain effects. These are direct prerequisites for the proposed slice.

**SNAP-02 covers live disk snapshot/revert and safe backing-graph transitions.** A cold auxiliary endpoint must refuse unsupported live capture and contributes no live graph implementation or SNAP-02 acceptance. Even SNAP-01 still needs complete disk/config capture, safe source-branch handling and actual revert/guest evidence beyond this endpoint.

[ADR 0020](../../docs/adr/0020-cold-recovery-boundary.md) already selects typed native-identity-bound capture, independently approved roots, confirmed stopped state, bounded sealed anonymous files and authenticated SCM_RIGHTS transfer. Auxiliary bytes must not enter JSON, logs, plans or helper journals. No broad ACL grant or generic root copy is authorized. Normative docs 07 and 10 require complete membership, leases and repeated source/native checks, followed by durable private staging and complete-set publication.

## Concrete blockers and unsafe composition paths

1. **Old policy must not silently acquire confidential-read authority.** `Policy` currently has global actors, keys and roots; it has no per-operation auxiliary permission. `Authorize` currently rejects every capture action. Extending that switch alone would let an already-approved signer request the new family using an old policy. Parent design must make the new bounded authority explicit, including permitted resource/member/root scope and byte/member limits. A valid signature proves which actor approved those parameters; it does not independently establish that a caller-selected file belongs to the requested VM. This is a prospective integration hazard, not a currently exposed capture exploit.

2. **Metadata observation must precede, and remain distinct from, copying.** `coldStateInspection` returns a successful result for running, managed-save, autostart and unresolved-path cases with warnings ([lines 49–62](../../internal/backend/libvirt/cold_state_linux.go)). The executor must convert incompatible conditions and unresolved required members into refusal. The ordinary-user `storageaccess.Plan` path takes a local file snapshot before calling the helper ([line 125](../../internal/storageaccess/service_linux.go)); that cannot bootstrap confidential files the actor cannot inspect. A separately authorized metadata-only native observation phase is needed to bind a fresh plan without opening bytes for the actor. This review does not resolve implicit native TPM locations.

3. **Root/path syntax and expected file identity do not establish root or VM authority.** `coldfiles.Open` accepts an approved-root argument but does not check root UID/GID/ACL/labels. Its `rootIdentity` is observed during Open, not supplied from the earlier plan. `fileidentity.Identity` contains generation, size, timestamps, links and mode, not owner/ACL/security-label observations. The endpoint must independently validate held root policy, bind current RootID resolution and exact native member identity, and retain any separately required restore metadata. Caller-chosen relative paths or an arbitrary XML path must never become privileged read scope by themselves. `openAccessFile` is not an auxiliary substitute: it has a different managed-volume contract and readable-open sequence.

4. **A guarded source duplicate is the wrong confidential response artifact.** `DupForTransfer` preserves source locks and read-only access, but the source remains a linked, mutable file. `validateSealed` correctly rejects it because snapshot descriptors must be anonymous and fully sealed ([lines 89–107](../../internal/helper/sealed_linux.go)). The helper must create an immutable copy before exposing the FD. It must call source/native rechecks before and after the copy and again at the complete-set boundary. `io.NewSectionReader(source, 0, size)` can adapt `ReadAt` safely, but its artificial EOF does not detect growth past the section: the post-copy identity/size check remains mandatory.

5. **Per-file locks do not establish a complete stopped interval.** [`AcquireReadGuard`](../../internal/backend/image/guard_linux.go) expressly implements cooperative QEMU file permission locks, excluding `locking=off` and non-QEMU writers. It does not prove swtpm or another producer stopped writing. Coordinator locks are database resources ([`Store.Accept`](../../internal/store/store.go)); they do not control another libvirt client or user. Parent design must specify the independently observed stopped interval, conflicting native jobs/writers, lease lifetime across all members, and final verification before publication. Releasing helper source references just after one FD send cannot by itself prove a coherent later disk/auxiliary set.

6. **Transport success is not correlated capture success.** The current client uses ordinary stream reads; those must not precede ancillary-message reception for the new response. `ReceiveSealedSnapshot` validates generic JSON only and requires exactly one FD even for an otherwise valid JSON frame. A dedicated typed success/error envelope is needed: errors expose no FD, successes bind operation/job/plan/resource/inventory/member/version/size/hash to the received bytes, and every later validation failure closes the FD. The existing generic JSON error response cannot simply be passed to this one-FD receiver while preserving typed failure meaning. The dedicated connection closes after its one response; do not reuse it or rely on the sender's shared OFD offset. Hash and stage through positional reads.

7. **Durable intent/result records cannot make anonymous delivery durable.** `journalAccess` is a reusable write-once/fsync pattern, but its `Complete` means an observed ACL effect. A memfd can disappear when its owners crash. A send can transfer the FD before a later stream write fails; conversely the helper can finish copying while the coordinator never receives it. Distinguish helper capture evidence, uncertain delivery and coordinator private-staging/publication proof. Reconciliation must inspect exact durable staged members and receipts; a helper-complete record or missing process is insufficient. If a fresh capture is necessary, it must have a newly authorized attempt or explicitly designed replay semantics with repeated immutable-input checks. No bytes belong in either journal.

8. **Limits and cancellation need an endpoint-level contract.** The primitive limit is one positive-size object, not a bounded member set or aggregate memory budget. Zero-length required files are accepted by `coldfiles` but refused by `CaptureSealed`; the endpoint must reject an unsupported required member visibly or obtain an explicit contract decision, never omit it. Multiple files cannot be silently squeezed through a one-FD contract without an agreed inventory/container or per-member protocol. The synchronous server's 10-second deadline and regular-file read limitation also require a declared bounded execution policy; a socket deadline does not forcibly cancel a blocked storage syscall. Keep native/file capability failures visible and leave no successful object on cancellation.

No currently exposed arbitrary-read path was demonstrated. These are missing checks and concrete incorrect ways of composing existing primitives. Native resolution, host confinement and multi-file publication still require their own implementations and qualification.

## Dependency-ordered implementation and tests

1. **Approve versioned authority and metadata contracts.** Define the auxiliary operation's explicit policy opt-in, exact native resource/root/member scope, immutable inventory/generation binding, aggregate limits, error envelope and durable receipt meaning. Keep legacy operations unable to carry new payloads. Test old-policy denial, wrong actor/key/action/root/VM/job/digest, expiry/revocation, foreign/missing/duplicate/versioned JSON fields and resource/member substitution before opening bytes.

2. **Implement independent metadata/native binding.** Bind the system connection, stable VM identity, exact persistent/effective configuration requirements, stopped/no-managed-save state, native producer/dependency membership and approved held roots to the plan. Test running or restarting VM, autostart policy, missing/added/reordered members, unresolved dependency, same path/new inode, same inode/changed bytes, root policy remap and unavailable generation/native capability. No test should treat caller-supplied XML or a parser warning list as proof.

3. **Compose held-source capture.** Reuse `coldfiles` and the existing lock protocol. Test pre/post-copy native/path/generation drift, FIFO/device/link/mount substitution before readable access, conflict/guard cleanup, short/long/zero/oversized sources, aggregate overflow, full-memory/write failure and cancellation at each boundary. Use original temporary files first; device/mount tests require separately authorized capabilities. Preserve all source artifacts and never publish an incomplete set.

4. **Wire a dedicated authenticated FD response.** Test both peer directions, policy reload, success versus zero-FD error framing, wrong/missing/extra FD, unsealed or substituted artifact, wrong correlation/hash/size, fragmented and partial responses, disconnect after FD arrival, offset manipulation, inherited-descriptor closure and descriptor counts after every failure. Existing sealed transport tests cover utility framing/seals; they do not replace endpoint authorization/correlation tests.

5. **Integrate the durable coordinator.** Register a separately versioned handler with exact domain/storage/member resource locks. Persist intent before privileged action. Privately stage and fsync held artifacts, verify every receipt and all members, and publish only the complete set. Inject death after intent, copy, seal, FD transfer, stage write/fsync, manifest publication and before final acknowledgement; reopen SQLite and helper records. Prove that missing, partial, altered or duplicate artifacts retain an incomplete/recovery-required result and that reconciliation never calls capture merely to infer success. Keep receipt compatibility explicit and preserve the old manifest checker's limited claims.

6. **Run native qualification only after those contracts/tests pass.** An authorized disposable guest must demonstrate the complete stopped capture, retained source branch, restore and identity behavior. Required helper policy/SELinux/AppArmor tests remain separate. Neither the previous marker boots nor this primitive review can satisfy that gate or SNAP-02.

## Local checks performed

The following existing tests were run with the pinned vendored toolchain, without root, external disk tools or host changes:

```sh
GOPROXY=off GOSUMDB=off ./scripts/go test -mod=vendor -race \
  ./internal/helper ./internal/backend/coldfiles \
  -run '^(TestGrantBindsPeerActionResourcesAndPlan|TestAccessAuthorityBindsEveryReviewedField|TestAccessPathRejectsAliasesAndUnrelatedFiles|TestAccessBindingAllowsOnlyFreshAuthentication|TestSealed|TestReadPinned|TestRefuse|TestFIFO|TestRecheck|TestPathReplacement|TestRootPathReplacement|TestTransferredGuard|TestBusyOpen|TestCancellationAndConcurrentClose)' \
  -count=1 -v
```

The command exited zero: helper `1.040s`, coldfiles `1.023s`. Authorization/binding, non-IPC sealed-copy failure/cancellation cases and all selected coldfiles cases passed under the race detector. **Every selected private Unix transfer case skipped at `net.FileConn` because `getsockopt` returned `operation not permitted`.** Parent test groups can print PASS while all transfer subcases are skipped; that is not passing SCM_RIGHTS evidence. No escalation was attempted. The gated real-QEMU test, root ACL mutation tests, native observer, actual helper server, coordinator capture/recovery and VM lifecycle were not run.

This document is the only deliverable changed for this assignment. The parent retains design, production contracts/runtime, evidence tracking and native execution ownership.
